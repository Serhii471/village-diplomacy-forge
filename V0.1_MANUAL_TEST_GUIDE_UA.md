# Village Diplomacy v0.1 — повна ручна перевірка release-кандидата

## Мета та правило доказовості

Перевіряйте точний commit у `master`, з якого буде створено реліз. Не переносіть результати зі старих гілок або JAR на новий commit. Реліз можна вважати готовим лише після проходження всіх обов'язкових етапів нижче без нових помилок у логах.

Перед початком запишіть:

```powershell
git status --short --branch
git rev-parse HEAD
java -version
```

Очікується Java 17, чиста `master` і версія Minecraft Forge 1.20.1-47.4.28. Не тестуйте на єдиній копії важливого світу: створіть окремий профіль і резервну копію.

## 1. Unit-тести та звичайна збірка

Із кореня репозиторію виконайте:

```powershell
.\gradlew.bat clean test build --no-daemon
```

Прийнятний результат:

- команда завершується з `BUILD SUCCESSFUL`;
- немає failures або errors;
- обов'язкові тести не пропущені;
- створено `build/libs/villagediplomacy-0.1.0.jar`.

Якщо цей етап не пройдено, не переходьте до гри й не створюйте тег.

## 2. Guard GameTests

```powershell
.\gradlew.bat -PguardGameTests runGameTestServer --offline
```

Якщо залежності ще не кешовані, один раз запустіть без `--offline`, а потім обов'язково повторіть із `--offline`. Перевірте, що всі guard-сценарії завершилися успішно, зокрема:

- прив'язка охоронця до поселення та NBT round trip;
- повернення до патрульної зони;
- припинення бою після зміни дипломатії;
- захист дружніх охоронців, лідерів, мешканців і големів;
- zombie/husk, skeleton, creeper, slime, magma cube та spider;
- збереження стандартної нейтральності умовно ворожих мобів;
- чотири спеціалізації текстури й базовий fallback;
- поведінка після повторного завантаження сутностей.

GameTest-збірка тимчасово підключає тестові source sets. Після неї обов'язково зберіть звичайний JAR ще раз:

```powershell
.\gradlew.bat clean test build --no-daemon --offline
```

## 3. Перевірка release JAR

```powershell
$jar = Resolve-Path '.\build\libs\villagediplomacy-0.1.0.jar'
$entries = jar tf $jar
$entries | Select-String 'VillageGuard|GuardHostility|GuardTargetGoal|textures/entity/guard'
$entries | Select-String 'gametest|skincheck|guard_arena|Garrison|ResidentData'
Get-FileHash $jar -Algorithm SHA256
tar -xOf $jar META-INF/mods.toml | Select-String 'version|authors'
```

У JAR мають бути:

- `VillageGuardEntity`, `VillageGuardRenderer`, `GuardHostilityEvents`, `GuardTargetGoal`;
- `guard_base.png`, `guard_plains.png`, `guard_mountain.png`, `guard_forest.png`.

Другий пошук не повинен показувати GameTest/skincheck, арену, гарнізон або `ResidentData`. У `mods.toml` мають бути версія `0.1.0` і автори `Arthur, Serhii`. Збережіть SHA-256 разом із commit.

## 4. Singleplayer у новому тестовому світі

Встановіть саме перевірений JAR у чистий Forge-профіль. Створіть окремий творчий світ і послідовно перевірте:

1. Мод завантажується, предмети та блоки мають назви й текстури, у журналі немає stack trace.
2. Leadership Seal призначає лідера лише після двох взаємодій із дзвоном; один гравець не стає лідером двох поселень.
3. Створіть два близькі поселення різних спеціалізацій. Diplomatic Scroll відкриває друге поселення.
4. Diplomacy Table працює в дозволеній зоні; усі чотири вкладки показують актуальні серверні дані.
5. Прийміть delivery або exchange contract. Передайте ресурси двома частинами, закрийте й повторно відкрийте GUI між передачами.
6. Завершіть контракт і переконайтеся, що винагорода видається один раз і не дублюється після повторного відкриття GUI.
7. Перевірте trade agreement, alliance, route, route map і два взаємні signpost.
8. Створіть охоронців для plains, mountain і forest та одного без визначеної спеціалізації. Перевірте відповідно три регіональні й базову текстури, а також звичайну броню поверх них.
9. Відведіть охоронця за межі зони: він має повернутися. Видаліть або змініть домашнє поселення: стара прив'язка й текстура не повинні залишатися.
10. Дружні охоронці не б'ються. Охоронець не атакує власного/союзного лідера, мирних мешканців і залізних големів. Після зміни HOSTILE на FRIENDLY/ALLY активний бій припиняється.
11. В окремій безпечній арені по черзі перевірте zombie або husk, skeleton, creeper, slime та magma cube. У темряві spider може нападати; при яскравому освітленні не повинен ставати безумовно агресивним.
12. Збережіть світ, повністю вийдіть із Minecraft, запустіть його знову й перевірте поселення, склади, контракти, договори, союзи, маршрути, guard home, патруль і текстуру.

Після тесту перегляньте `logs/latest.log`. Будь-який новий crash, stack trace, missing texture або мережева помилка є причиною зупинити реліз.

## 5. Dedicated server

Використайте окрему серверну директорію та той самий JAR на сервері й клієнті.

1. Сервер запускається без client-only помилок.
2. Клієнт підключається без mismatch або помилки мережевого протоколу.
3. Diplomacy Table отримує актуальні дані із сервера.
4. Гравець без прав лідера не може виконувати захищені дії.
5. Контракт, часткова передача ресурсів і винагорода синхронізуються.
6. Охоронець, броня й регіональна текстура однаково відображаються після reconnect.
7. Після повної зупинки й повторного запуску сервера зберігаються поселення, склади, контракти, договори, союзи, маршрути та прив'язка охоронця.
8. У серверному й клієнтському логах немає нових stack trace, missing texture або помилок пакетів.

## 6. Фінальна репетиція та рішення

Виконайте повний сценарій із `docs/demo/v0.1-presentation-runbook.md` на копії демосвіту. Зафіксуйте:

- commit `master`;
- SHA-256 JAR;
- кількість unit-тестів і GameTests;
- версії Java, Forge та Minecraft;
- результати singleplayer і dedicated server;
- відомі обмеження;
- скриншоти чотирьох guard-текстур.

Не створюйте `v0.1.0` і не публікуйте JAR, якщо хоча б один обов'язковий етап не пройдено. Окремо підтвердьте право на розповсюдження базової guard-текстури або замініть її на ресурс із підтвердженою ліцензією.
