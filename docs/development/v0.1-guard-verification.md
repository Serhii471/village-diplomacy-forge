# Verify and integrate the v0.1 guard package

Current base commit: `10d4fbd1f6f9e162b2501b9333632e9dcd737aeb`. Branch: `serhii/v0.1-guards`.
The four commits are ordered patrol → hostile targets → uniforms → verification.
Use `git log --reverse --oneline 10d4fbd..serhii/v0.1-guards` for their current hashes.

These commands were not run after replaying the guard commits on the current integration base. Historical results from the earlier `daaf840`-based package are not proof for the current commit. Run the full sequence before tagging or publishing v0.1.0.

Only guard production classes/assets are adapted. Shared trade, network, GUI,
localization, version and author metadata are retained from the pinned base.
No resident/garrison feature, schema, resource or test is imported.

## Commands

Use Java 17 and run Gradle commands sequentially:

```powershell
.\gradlew.bat test build --no-daemon
.\gradlew.bat -PguardGameTests runGameTestServer --offline
```

The optional GameTest source set includes 25 guard scenarios: patrol, persisted
home, return navigation, protected targets, diplomacy changes, hostile mobs,
regional uniforms/fallback, and encoded tracking metadata. Each run creates a new
world below `build/guard-gametest-runs`. Hostile cases run in isolated batches so
vanilla higher-priority targets in another arena cannot affect their result.
Batch cleanup is intended for these disposable test-server worlds only.

For the optional two-client check, choose a new directory each time:

```powershell
.\gradlew.bat -PguardSkinCheck -PguardSkinCheckDir=build/v01-guard-client-check writeGuardSkinCheckLaunch --offline
node tools/run_guard_skin_check.cjs build/v01-guard-client-check
```

It launches a localhost-only dedicated server and two development clients using
separate world/config directories. It verifies eight real tracked guards per
viewer, four textures with/without chainmail, all skin layers, live specialization
changes, removed-home fallback and full server save/restart/reconnect. It captures
screenshots through Minecraft and does not send mouse/keyboard input.

After optional checks, rebuild the regular JAR so it excludes test/harness code:

```powershell
.\gradlew.bat test build --no-daemon --offline
python tools/verify_v01_guard_package.py
```

The verification script reads the actual XML test results, server log, client
result and release archive; it writes `build/v01-guard-verification.json`.

## Evidence limits and teammate handoff

Headless GameTests establish server behavior. The client gallery verifies guard
rendering and multiplayer tracking, not a complete diplomacy/trade playthrough or
combat animations. The final JAR retains the base's trade core, but the two authors
must still rehearse the full presentation on the integrated build. Redistribution
permission for the base guard skin was confirmed on 2026-11-24; see `v0.1-guard-assets.md`.

The generated handoff folder includes four binary-capable patch files, a Git
bundle, the regular JAR, verification summary, screenshots and a Ukrainian guide.
It excludes launch manifests/environment variables, local worlds/configs, IDE
files, caches and raw game binaries. Sending/uploading it is a separate action.
