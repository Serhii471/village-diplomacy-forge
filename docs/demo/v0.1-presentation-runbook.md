# Village Diplomacy v0.1 Presentation Runbook

## Purpose

This runbook defines a repeatable demo-world state and presentation sequence for Village Diplomacy v0.1. Build the final world only after the guard integration is complete so the saved data and runtime assets match the release JAR.

## Release candidate prerequisites

Before preparing the world, confirm:

- the branch contains the final diplomacy core and standalone guard integration;
- `mod_version=0.1.0` and both authors appear in the mod list;
- Java 17, Minecraft 1.20.1, and Forge 47.4.28 are used;
- `gradlew.bat test build --no-daemon` succeeds;
- guard GameTests succeed;
- the release JAR contains the four runtime guard textures;
- no development-only classes or GameTest arenas appear in the release JAR.

## Demo-world layout

Prepare two compact settlements in the same dimension and keep travel time below one minute.

### Settlement A

- Claimed by the presentation player.
- Has a central Bell and a Diplomacy Table within 32 blocks.
- Uses one clear specialization, preferably plains.
- Contains a Route Signpost near the exit road.
- Contains one regional guard.

### Settlement B

- Remains leaderless so server-side diplomatic decisions can be demonstrated predictably.
- Uses a different specialization, preferably forest or mountain.
- Has a central Bell and a second reciprocal Route Signpost.
- Contains one regional guard with a visibly different uniform.

### Combat area

- Place it outside civilian traffic but inside or near the guard patrol boundary.
- Keep enough space for navigation and ranged combat.
- Use a normal hostile mob without `NoAI`.
- Keep a backup before every rehearsal so mob or guard deaths do not alter the next run.

## Required saved state

The clean presentation backup must contain:

- both settlements registered and specialized;
- the presentation player leading Settlement A;
- Settlement B discovered by Diplomatic Scroll;
- both warehouses holding enough complementary goods;
- at least one visible trade offer;
- no expired contract blocking an alliance demonstration;
- a route connecting the two settlements;
- reciprocal configured signposts;
- guards assigned to their settlements;
- no unrelated mobs, raids, weather, or inventory clutter that can disrupt the demo.

Prefer a visible offer that can be completed with two partial handovers. Keep the required items in a clearly labeled chest only as an emergency fallback; the normal demo must use the representative handover flow.

## Presentation inventory

Prepare:

- Leadership Seal;
- Diplomatic Scroll;
- ordinary contract goods;
- Trade Route Map;
- one spare Route Signpost;
- food and non-distracting basic equipment;
- no unrelated mod items.

## Rehearsal sequence

1. Show the mod list, version `0.1.0`, and both authors.
2. Introduce Settlement A and its specialization.
3. Open the Diplomacy Table and show the settlement, relations, trade, and route tabs.
4. Show Settlement B as a known settlement with a different specialization.
5. Accept a trade offer at the table.
6. Use the Bell representative to collect ordinary Minecraft resources.
7. Travel along the marked route to Settlement B.
8. Deliver only part of the goods and show persisted partial progress.
9. Deliver the remainder and claim the reward once.
10. Show the agreement and alliance controls or their prepared eligible states.
11. Show the route map and both reciprocal signposts, including direction and distance.
12. Compare the two regional guard uniforms.
13. Spawn or reveal one normal hostile mob and show mutual combat with the guard.
14. Save and exit, reopen the world, and confirm that settlements, contract history, route state, and guard assignment persist.
15. End with the 0.2.x roadmap: human residents, professions, recruitment, and garrison management.

## Dedicated-server rehearsal

Using the same release JAR on server and client:

- connect with a normal player account;
- open the Diplomacy Table and verify current server data;
- confirm a non-leader cannot perform leader-only actions;
- complete one handover action;
- disconnect and reconnect;
- restart the server and confirm persistence;
- verify guard rendering and behavior after reconnect.

Do not use the presentation backup for experimental debugging. Work on a copy and restore the clean backup after every rehearsal.
